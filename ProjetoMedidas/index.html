Slide 2 — Conceito
Dois grandes grupos de unidades
Classificação do W3C. Fonte: w3.org/Style/Examples/007/units.pt_BR.html

Segundo o W3C, as unidades absolutas significam em CSS o mesmo que em qualquer outro lugar — aparecem exatamente do tamanho que são, dentro da precisão do hardware. Porém não são recomendadas para tela, porque tamanhos de tela variam muito: uma tela grande pode ter 60cm, uma portátil talvez 8cm — e você não as olha da mesma distância.

Absolutas

Valor independente de contexto

Não dependem do pai, do root nem da janela. O valor é sempre o mesmo — por isso são previsíveis mas inflexíveis.

Na tela: px  |  Impressão: cm mm pt pc

Relativas

Valor proporcional a uma referência

Dependem de outra coisa: o pai, o root do documento, o tamanho da janela, ou a própria fonte. Essenciais para responsividade.

em rem % vw vh ch

Recomendação do W3C para tela: use em, px e % — evite cm, mm, in, pt e pc em folhas de estilo para monitor. Para impressão, inverta: prefira cm, pt, e evite px.
CSS/* Absoluta — sempre 300px, não importa o contexto */ .caixa { width: 300px; } /* Relativa ao pai */ .caixa { width: 50%; } /* Relativa ao root (elemento html) */ .caixa { font-size: 1.5rem; } /* Relativa à janela do navegador */ .hero { height: 100vh; }

O px é chamado de "unidade mágica" pelo W3C. Não é relacionado à fonte nem a medidas físicas exatas — é definido para ser pequeno, mas visível. Garante aparência consistente entre dispositivos, o que o torna o mais seguro para tela. Imagens rasterizadas são exibidas por padrão com mapeamento de 1px por pixel.

Acessibilidade: quando o usuário aumenta o tamanho padrão do texto no navegador, fontes definidas em px não respondem. Para fontes, prefira sempre rem.
Bom uso de px.card { border: 1px solid #ddd; border-radius: 8px; box-shadow: 0 2px 8px rgba(0,0,0,.1); outline: 2px solid blue; } /* px é ideal para valores que não devem escalar com o texto */
Fonte: px vs rembody { /* Ruim — ignora configuração do navegador */ font-size: 16px; } body { /* Bom — respeita preferência do usuário */ font-size: 1rem; }
Slide 4 — em e rem
As unidades relativas mais usadas
Segundo o MDN, em e rem são as unidades relativas que você encontrará com mais frequência ao dimensionar textos e caixas. Fonte: MDN Web Docs

em — relativo ao pai

em é o tamanho de fonte do elemento atual. Em um elemento com fonte 20px, 1em = 20px. Quando usado para font-size, o pai é a referência; para outras propriedades (padding, margin), o próprio elemento é a referência.

Cascateamento: cada filho herda e multiplica pelo pai. Com 1.2em em cada nível: 14px → 16,8px → 20,16px → 24,2px. O texto cresce sem parar.

rem — relativo ao root

rem significa "root em" — sempre se refere ao <html>, não ao pai. O valor de root é constante em todo o documento. O problema do cascateamento simplesmente não existe.

Vantagem: alterar o font-size do html reescala tudo proporcionalmente. Perfeito para acessibilidade e temas escaláveis.
Problema com em/* html: 16px padrão, pai: 14px */ .pai { font-size: 14px; } .filho { font-size: 1.2em; /* 14 × 1.2 = 16.8px */ } .neto { font-size: 1.2em; /* 16.8 × 1.2 = 20.16px */ } /* cascata acumulada! */
Solução com remhtml { font-size: 16px; } h1 { font-size: 2rem; } /* 32px */ h2 { font-size: 1.5rem; } /* 24px */ p { font-size: 1rem; } /* 16px */ small { font-size: .75rem; } /* 12px */ /* sempre relativo ao html */

Slide 5 — Porcentagem
A unidade %
Sempre relativa ao pai — mas o que é o "pai" muda conforme a propriedade. Fonte: MDN Web Docs

Para width e height, a porcentagem é relativa à dimensão correspondente do pai. Para font-size, é relativa à fonte do pai. Para margin e padding — incluindo top e bottom — a referência é sempre a largura do pai. Isso surpreende muita gente.

Largura fluida.pai { width: 800px; } .filho { width: 50%; } /* = 400px */ .neto { width: 50%; } /* = 200px */ /* padding-top em % usa a LARGURA do pai — não a altura! */ .thumb { width: 100%; padding-top: 56.25%; /* aspect ratio 16:9 */ }
Por que height: 50% às vezes não funciona? Se o pai não tem altura definida, o navegador não sabe calcular 50% de quê — o resultado é 0. O pai precisa de height explícito ou ser 100vh.

Slide 6 — Viewport
vw, vh, vmin e vmax
Relativas ao tamanho da janela do navegador — não ao elemento pai. Fonte: desenvolvimentoparaweb.com

vw e vh são relativas à viewport — a área visível da janela. 1vw = 1/100 da largura; 1vh = 1/100 da altura. Se a viewport tem 900px de altura, 1vh = 9px. Se tem 750px de largura, 1vw = 7,5px.

vmin e vmax combinam os dois: vmin usa o menor valor entre vw e vh, e vmax usa o maior. Para uma viewport de 1100×700px: 1vmin = 7px e 1vmax = 11px.

Unidade Referência Exemplo concreto (viewport 1100×700)
vw 1% da largura da viewport 1vw = 11px
vh 1% da altura da viewport 1vh = 7px
vmin 1% do menor (vh = 700) 1vmin = 7px
vmax 1% do maior (vw = 1100) 1vmax = 11px
Usos clássicos/* Seção que ocupa a janela inteira */ .hero { min-height: 100vh; } /* Elemento quadrado sempre visível */ .square { width: 80vmin; height: 80vmin; } /* Título que escala com a tela */ h1 { font-size: 5vw; }
Problema no mobile/* vh tem comportamento inconsistente em iOS e Android: as barras do navegador mudam a altura real */ /* Novas unidades CSS (suporte moderno) */ .hero { /* svh = smaller viewport height */ /* (com barras visíveis) */ min-height: 100svh; /* dvh = dynamic (muda ao rolar) */ min-height: 100dvh; }

Slide 7 — ch e ex
Unidades tipográficas: ch e ex
Dependem da família de fonte, não apenas do tamanho. Fonte: desenvolvimentoparaweb.com
ch

Largura do caractere "0"

Definida como a advance measure (medida de avanço) da largura do caractere "0" na fonte atual. Em fontes monoespaçadas, width: 40ch garante exatamente 40 caracteres na linha.

O uso mais comum é definir max-width de parágrafos: textos com 60–75 caracteres por linha são considerados ideais para leitura. Com max-width: 65ch, isso se ajusta automaticamente a qualquer tamanho de fonte.

ex

Altura da letra "x" minúscula

Definida como a x-height — altura da letra "x" minúscula na fonte atual. Fontes com o mesmo em podem ter ex muito diferente, pois cada família tem proporções próprias.

É raramente usada no dia a dia, mas útil para alinhar ícones inline com o texto de forma tipograficamente precisa — o ícone fica na altura exata das letras minúsculas.

Usos práticos de ch/* Largura de leitura ideal em artigos */ article p { max-width: 65ch; /* ~65 caracteres por linha */ line-height: 1.65; } /* Input que cabe exatamente um CEP */ input.cep { width: 9ch; } /* "00000-000" = 9 chars */ /* Input que cabe um CPF */ input.cpf { width: 14ch; } /* "000.000.000-00" = 14 chars */ /* Gap no tamanho de um espaço */ .inline-tags { gap: 1ch; }
Demo — max-width com ch
Este parágrafo tem max-width em ch. Ao aumentar a fonte, a caixa também fica mais larga — porque ch é proporcional ao caractere da fonte. A largura ideal de leitura acompanha o texto automaticamente.

Perceba: diferente de px, o limite em ch cresce quando o texto cresce.

Slide 8 — Tipografia fluida
clamp() — unidades combinadas
A técnica moderna de tipografia fluida que elimina a necessidade de media queries para fontes. Fonte: MDN — CSS length

A função clamp(mínimo, ideal, máximo) restringe um valor entre um mínimo e máximo, mas o deixa variar de forma fluida entre eles. Combinada com vw, cria fontes que escalam automaticamente com a largura da tela — sem nenhuma media query.

Tipografia fluida com clamp/* Abordagem antiga: media queries para cada breakpoint */ h1 { font-size: 1.75rem; } @media (min-width: 768px) { h1 { font-size: 2.5rem; } } @media (min-width: 1200px) { h1 { font-size: 3rem; } } /* Abordagem moderna: uma linha só */ h1 { /* min: 1.75rem | ideal: 4vw | max: 3rem */ font-size: clamp(1.75rem, 4vw, 3rem); } p { font-size: clamp(0.9rem, 2.5vw, 1.2rem); max-width: 65ch; }

Alinhamento de ícones
% vs vw — a diferença que mais confunde: % é relativa ao pai. Se o pai tem 600px e o elemento tem containers com padding, 100% pode ser menos que a largura da tela. vw é sempre relativa à janela — ignora completamente a hierarquia de elementos.
em vs rem — qual escolher? Use rem para fontes e espaçamentos globais — é previsível. Use em para padding/gap dentro de componentes — o componente inteiro escala proporcionalmente à sua própria fonte.
Slide 11 — Boas práticas
Quando usar cada unidade
Guia de decisão baseado nas recomendações do W3C, MDN Web Docs, W3Schools e desenvolvimentoparaweb.com.
px

Valores fixos e precisos

Bordas, outline, box-shadow, border-radius. Alinhamento pixel-perfect de imagens com texto. Tamanho fixo de ícones SVG.

rem

Fontes e espaçamentos globais

Tamanho de fonte de toda a aplicação. Margens e paddings de elementos de conteúdo. max-width de containers.

em

Contexto interno de componente

Padding e gap de botões, badges, cards. O componente inteiro escala ao mudar apenas a font-size dele.

%

Larguras de layout

Colunas em grids e flexbox. Largura de imagens dentro do container. Padding-top para aspect ratio legado.

vw / vh

Dimensões relativas à janela

Hero sections (min-height: 100svh). Tipografia fluida com clamp(). Modais e overlays de tela cheia.

ch

Largura de leitura ideal

max-width: 65ch em artigos e parágrafos. Inputs com tamanho exato para um número de caracteres.

Sistema completo usando todas as unidadeshtml { font-size: 16px; } /* root — base para rem */ .layout { max-width: 75rem; /* container: 1200px */ padding: 0 5%; /* margens fluidas */ } .hero { min-height: 100svh; /* altura da janela, mobile-safe */ padding: 4rem 0; } h1 { font-size: clamp(1.75rem, 4vw, 3rem); } p { max-width: 65ch; line-height: 1.65; } .btn { padding: .7em 1.5em; /* escala com a fonte do botão */ border: 1px solid currentColor; /* borda sempre nítida */ border-radius: 6px; }
